# Fitlog 健身卡通动作 GIF 生成指南

日期：2026-10-30

原图本机副本：`.local-tools/bench-preview/reference-original.png`（Git 忽略，换机时需重新提供原图）。

## 1. 制作目标与依据

制作可重复播放的健身动作指导 GIF，以用户提供的“像素小狗杠铃卧推”原图为角色及画风基准。先绘制动作关键帧供用户预览，再转为 PDF 供整体审阅；关键帧确认后，才扩展连续帧并合成 GIF。

用户原图优先于后续生成图。此前两版生成图均为探索稿，不能作为新的角色或画风标准，尤其不能沿用第二版较长的腿和更接近普通插画的比例。早期灰白解剖人体图只用于说明动作演示的用途，不是本次视觉风格依据。

当前先以杠铃卧推试制一个完整动作周期；其他动作逐个确定具体变式，不把一个动作的关节轨迹直接套用到其他动作。

## 2. 用户明确提出的要求

- 保持原图的轻像素画风，不能在修改姿势时改变画风。
- 小狗应更卡通、圆润，保留原角色的短腿比例，不能为了展示动作而拉长腿。
- 先画几个动作关键帧，先看预览，并转为 PDF。
- 动作必须正确，制作过程要有动作科学性的依据和核对。
- 最终 GIF 只需重复动作，不需要额外剧情或复杂演出。
- 帧间过渡必须清晰，动作阶段能看明白，循环衔接自然。

以下技术参数为试制建议，可按预览结果调整，不视为用户已经确认的固定规格。

## 3. 固定角色与轻像素风格

### 角色

使用原图中的金黄与奶油白小狗，保留头部轮廓、口鼻、耳朵、脸部特征、圆润躯干、短四肢和爪部造型。整体可爱、卡通，避免写实人体、肌肉雕刻、细长四肢和明显的人体手脚。

卡通角色可以拟人化完成动作，但关节运动和器械接触必须可理解。若短腿无法接触地面，应调整凳高或增加稳定脚踏，不靠拉长腿解决。示意图若使用脚踏，连续帧中保持脚踏位置和尺寸不变。

### 视觉

用户补充的三张小狗参考图用于进一步约束像素颗粒与角色造型，优先于此前生成稿。本机副本为 `.local-tools/bench-preview/reference-finepixel-1.png` 至 `reference-finepixel-3.png`。要求像素颗粒更细、轮廓更轻、色阶柔和，保留短腿、大耳朵、白色口鼻和紧凑卡通比例；禁止大块马赛克、粗重阶梯边缘及放大低分辨率精灵图的观感。以相同角色显示尺寸比较颗粒，不能只通过提高导出分辨率宣称粒度变细。

沿用原图深蓝灰轮廓、蓝灰器械、金黄毛色、奶油白面部与腹部，以及浅暖色背景。轮廓和阴影保持克制，有可辨识的像素阶梯与有限色阶，同时保留原图柔和、轻盈的观感。

禁止向高清光滑插画、写实三维、厚涂、过度抖色或极粗硬像素风漂移。不能仅通过增加分辨率、模糊滤镜或堆叠细节来“提升质量”。

### 跨帧一致性

同一动作锁定角色比例、像素颗粒尺度、配色、光照、画布、相机、地面和器械。头、身体、凳子和杠铃不能随动作忽大忽小；杠铃片数量、大小、握距保持一致。

必要时先单独确认角色静态样张，再绘制动作。每次生成都带入用户原图作为主参考，不能只依赖上一张生成图，以免误差逐轮累积。

## 4. 动作正确性与可读性

先明确动作名称、变式、起止姿势、支撑点、运动范围、器械轨迹及主要易错点，再设计关键帧。区分通用原则与因个体比例、活动度而变化的细节，不把某个固定角度称为适用于所有人的唯一标准。

卡通化可以简化外形，不能改变基本运动逻辑。逐帧核对：

- 关节弯曲方向合理，没有反关节、断肢、额外肢体或肢体融合。
- 手爪与器械接触稳定，握持明确，没有滑脱、穿模或悬空握持。
- 身体支撑可信，脚、凳子、地面之间没有漂移或穿透。
- 起点、下放、底端、推起等阶段确实不同，而不是同姿势上下平移。
- 运动范围、器械路径与所选动作变式一致。

杠铃卧推的初始核对重点：头、上背和臀部有稳定凳面支撑；双脚落地或踩在稳定脚踏上；握持闭合；手腕与前臂基本对齐；下放受控；底端落点位于胸部区域，不能落在面部、颈部或腹部；不靠反弹或抬臀完成推起。具体底端深度按选定示范版本确定。

视角首先服务于动作辨识，同时尽量接近原图的轻度斜视角。若杠铃片遮住手腕、肘部或胸部落点，应调整视角或器械显示方式，不能靠文字说明掩盖错误画面。不能为了看清动作，把角色比例改成长腿人体。

生成模型不能自行提供动作科学性保证。制作时引用可靠的动作指南，并核查其具体变式；正式用于教学前，应由有资质的教练复核。未经复核的素材标注为设计预览，不宣称已获专业审核。

## 5. 制作与预览顺序

1. **确认样张**：以原图锁定小狗比例、短腿、配色和轻像素颗粒。
2. **设计关键帧**：每个动作先画 4～6 个主要阶段。卧推可先用顶端准备、下放中段、底端位置、推起中段四帧，最后回到顶端。
3. **检查风格与动作**：先排除比例变化和动作错误，再进入排版；不合格帧先重画。
4. **提供预览与 PDF**：同一视角、同一尺度并排展示，编号并附简短阶段说明。PDF 保留清晰图像比例，不能裁掉器械和支撑点。
5. **用户确认关键帧后补连续帧**：沿已经确认的姿势和运动路径补中间帧。先生成关键帧不等于已经获得继续制作整套动作的确认。
6. **合成与回看**：检查原速、慢速和循环接缝。发现错误时修正源帧，不能仅靠加速、模糊或补帧隐藏。

## 6. 清晰过渡与无缝循环

帧过渡应表现真实姿势变化，不能通过两张静态图交叉淡化形成重影。手爪、肘部、器械边缘保持清晰，避免运动模糊、拖影和闪烁。

下降、底端转向、上升与顶端转向应有自然节奏，不做突然瞬移。循环首尾的姿态与运动方向连续；避免重复首帧造成额外停顿。器械与身体的接触约束在整个周期保持成立。

试制可从每周期约 3～5 秒、每秒 20～25 帧开始，按动作调整。GIF 的帧时长以百分之一秒为单位，20 fps 或 25 fps 便于均匀编码。帧数多不代表动作正确，清晰度和运动路径优先。

尽量采用稳定的共享调色板，减少颜色闪动；缩放保持像素边缘，避免反复重采样。浅色纯背景优先贴近参考图；透明背景如有需要单独确认，并检查 GIF 透明边缘。

## 7. 交付与验收

此后所有生成的 GIF 均按动作中文名称命名，例如 `杠铃卧推.gif`，统一保存到项目 `resource/`，即 `\\wsl.localhost\Ubuntu\home\lzk\projects\fitlog\resource`。不同动作变式使用明确的动作名称，不使用英文临时名作为交付文件名。已有同名文件时，未获覆盖授权不得覆盖，应保留版本。

关键帧阶段交付预览 PNG 和 PDF；GIF 阶段交付循环 GIF，并保留无损 PNG 连续帧，便于后续修改。正式素材和预览稿明确区分，预览不直接覆盖应用现有资源。

交付前同时满足以下条件：

- 一眼看出是原参考图的小狗，仍是短腿、圆润、轻像素风格。
- 各帧角色、视角、器械和像素尺度一致。
- 支撑、握持、关节方向和动作轨迹合理，无明显穿模或漂移。
- 每个关键阶段清楚可辨，连续播放无重影、闪动和突跳。
- 能自然反复播放，不依赖镜头运动、装饰特效或剧情。
- 审核状态和动作依据如实说明，不以视觉检查代替专业认证。

## 8. 可复用生成提示词

> 以用户提供的“像素小狗杠铃卧推”原图为主参考，制作【动作名称与变式】的【阶段名称／关键帧组】。严格保持原图轻像素风格：金黄与奶油白小狗、圆润卡通躯干、原有短腿与短肢比例、深蓝灰轮廓、蓝灰器械、柔和有限色阶和浅暖背景。不要拉长腿，不要改成人体比例，不要转为光滑高清插画或写实三维。固定相机、画布、角色尺度、器械大小和配色。动作规范：【支撑点、关节运动、握持、器械路径、起止姿势】。短腿需要支撑时调整器械高度或使用稳定脚踏，不能改变角色比例。各阶段姿势差异清楚，接触稳定，无反关节、额外肢体、穿模、漂移、运动模糊或重影。只表达完整重复动作所需阶段，不增加剧情、镜头运动或装饰特效。若风格与动作展示冲突，先调整构图和器械，不牺牲角色一致性或动作合理性。
